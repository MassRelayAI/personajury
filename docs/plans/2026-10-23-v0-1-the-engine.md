# JuryPersona v0.1 — the engine — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One Rust binary, `jurypersona`, that stores personas, panels, lenses, subjects, comparators, runs, verdicts and decisions in SQLite, composes deterministic hashed briefs, refuses verdicts without evidence, reports per stratum and never across, diffs rounds and classifies diffs — and never calls a model.

**Architecture:** The rings of CompareGraph: `domain/` (pure: types, hashes, the refusals, matrix, delta, trigger classifier) ← `store/` (SQLite, append-only verdicts and decisions) ← `application/` (one module per verb) ← `adapters/` (clap CLI, stdio MCP, the envelope). The agent runs the personas: `brief` → its own subagents → `verdict`.

**Tech Stack:** Rust 1.98.1 (pinned), clap 4, rusqlite 0.32 bundled, serde/serde_json, sha2+hex, thiserror, toml 0.8, globset 0.4; dev: assert_cmd, predicates, tempfile. Apache-2.0.

> **Amended:** D6 (docs/decisions.md) changes the verdict contract after this plan was written: `about` replaces `comparator`, one line per (dimension, about), integer lower-middle median, five new refusal codes. Where this plan and D6 differ, D6 wins.

**Spec:** the design report (kept privately by the maintainer; docs/design.md is its public summary) (§2, §3, §4, §5, §10 are law; where this plan and the report differ, the report wins). Decision of record: D1.

## Global Constraints

- The engine never calls a model, never reads an env var for a key or token, never fetches the network. No HTTP crate in `Cargo.lock` (test `no_network_crate_in_lock`).
- No new dependency beyond the Tech Stack line; `Cargo.lock` is written once in Task 0 and never edited by a worker.
- Store at `<root>/.jurypersona/store.db`, `--root` global flag, default `.`. Blobs at `<root>/.jurypersona/blobs/<sha256>`.
- Every verb answers with CompareGraph's envelope (`ok, verb, schema, data, evidence, cost, error`); exit 0 on ok, 1 on error.
- Verdicts and decisions are append-only: SQLite triggers abort UPDATE and DELETE on `verdict`, `pick`, `decision`.
- No score is ever averaged across strata. Within a stratum the matrix shows every score, the median, min and max — no mean anywhere.
- Scores are integers on the lens scale (shipped lenses: 1–5, anchors in words at 1, 3, 5).
- Determinism: same inputs → byte-identical brief and the same hash; every list sorted or in a stated order.
- Files a worker copies from CompareGraph carry a first-line comment `// adapted from comparegraph <path>` (or `#`/`<!-- -->` for the file type).
- Commits: conventional; stage named paths; never `git add -A`, never `--no-verify`; `cargo fmt` only on files you wrote (`rustfmt <file>`), never the crate.
- Tests run through `tools/pidns-run.sh` (the cargo runner). `--apply` tests use a temp HOME only.
- Spend is adjustable on two axes (D3: spend must be adjustable from low to high): how many
  personas × lenses (`--spend`, the lens choice) and how much each brief and answer carries (`--detail compact|full`, default
  `compact`, on `brief`, `matrix` and their MCP tools). Every brief reports its byte size; nothing estimates tokens by guess.

## Review Focus

1. A verdict file that is not valid JSON or misses `persona`/`lines` → `invalid_arguments` naming the field, never a panic (Task 5, `verdict_malformed_json_is_invalid_arguments`).
2. An attachment whose source file was deleted after `subject add` → `check` reports the run stale (`source_missing`), `verdict` refuses with `subject_moved` (Task 5, `deleted_source_counts_as_moved`).
3. A persona re-added with changed text mid-run → the run keeps the version it briefed; the verdict is stored against that version (Task 4, `brief_pins_persona_version`).
4. A diff with renames and a path matching two rules → the highest quorum wins and both rules are listed (Task 1, `classify_takes_highest_quorum`).
5. Two verdict ingests for the same (run, persona) → the latest batch wins in `matrix`; `--history` shows both (Task 5, `latest_ingest_wins_history_shows_all`).

## Store schema (Task 2 writes it verbatim into `store/schema.sql`)

```sql
CREATE TABLE IF NOT EXISTS meta (key TEXT PRIMARY KEY, value TEXT NOT NULL);
CREATE TABLE IF NOT EXISTS persona (
  id TEXT NOT NULL, version INTEGER NOT NULL, name TEXT NOT NULL, tags_json TEXT NOT NULL, stake_rules TEXT NOT NULL,
  profile_json TEXT NOT NULL, origin TEXT NOT NULL, hash TEXT NOT NULL, created_at TEXT NOT NULL, PRIMARY KEY (id, version));
CREATE TABLE IF NOT EXISTS material (hash TEXT PRIMARY KEY, sources_json TEXT NOT NULL, brief_path TEXT NOT NULL, created_at TEXT NOT NULL);
CREATE TABLE IF NOT EXISTS panel (
  name TEXT PRIMARY KEY, query TEXT NOT NULL, persona_ids_json TEXT NOT NULL DEFAULT '[]', hash TEXT, created_at TEXT NOT NULL);
CREATE TABLE IF NOT EXISTS lens (
  name TEXT NOT NULL, version INTEGER NOT NULL, body_json TEXT NOT NULL, hash TEXT NOT NULL, created_at TEXT NOT NULL,
  PRIMARY KEY (name, version));
CREATE TABLE IF NOT EXISTS subject (
  name TEXT NOT NULL, version INTEGER NOT NULL, kind TEXT NOT NULL, is_comparator INTEGER NOT NULL, hash TEXT NOT NULL,
  created_at TEXT NOT NULL, PRIMARY KEY (name, version));
CREATE TABLE IF NOT EXISTS attachment (
  subject_name TEXT NOT NULL, subject_version INTEGER NOT NULL, label TEXT NOT NULL, media TEXT NOT NULL, hash TEXT NOT NULL,
  source_path TEXT NOT NULL, PRIMARY KEY (subject_name, subject_version, label),
  FOREIGN KEY (subject_name, subject_version) REFERENCES subject(name, version));
CREATE TABLE IF NOT EXISTS run (
  id INTEGER PRIMARY KEY, subject_name TEXT NOT NULL, subject_version INTEGER NOT NULL, subject_hash TEXT NOT NULL,
  panel_name TEXT NOT NULL, panel_hash TEXT NOT NULL, lens_name TEXT NOT NULL, lens_version INTEGER NOT NULL,
  model TEXT NOT NULL, spend INTEGER NOT NULL, stakes_json TEXT NOT NULL, personas_json TEXT NOT NULL,
  comparators_json TEXT NOT NULL, briefs_json TEXT NOT NULL, created_at TEXT NOT NULL);
CREATE TABLE IF NOT EXISTS verdict (
  id INTEGER PRIMARY KEY, run_id INTEGER NOT NULL REFERENCES run(id), batch INTEGER NOT NULL, persona_id TEXT NOT NULL,
  persona_version INTEGER NOT NULL, dimension TEXT NOT NULL, score INTEGER NOT NULL, anchor_met INTEGER NOT NULL,
  evidence TEXT NOT NULL, comparator TEXT, citations_json TEXT NOT NULL, citation_hash TEXT NOT NULL,
  blockers_json TEXT NOT NULL, note TEXT, created_at TEXT NOT NULL);
CREATE INDEX IF NOT EXISTS idx_verdict_run ON verdict(run_id, persona_id, batch);
CREATE TABLE IF NOT EXISTS pick (
  id INTEGER PRIMARY KEY, run_id INTEGER NOT NULL REFERENCES run(id), batch INTEGER NOT NULL, persona_id TEXT NOT NULL,
  choice TEXT NOT NULL, reason TEXT NOT NULL, created_at TEXT NOT NULL);
CREATE TABLE IF NOT EXISTS finding (
  id TEXT PRIMARY KEY, run_id INTEGER NOT NULL REFERENCES run(id), batch INTEGER NOT NULL, persona_id TEXT NOT NULL,
  subject_name TEXT NOT NULL, dimension TEXT NOT NULL, text TEXT NOT NULL, citation_hash TEXT NOT NULL);
CREATE TABLE IF NOT EXISTS decision (
  id INTEGER PRIMARY KEY, finding_id TEXT NOT NULL REFERENCES finding(id), outcome TEXT NOT NULL CHECK (outcome IN ('fixed','dismissed','row')),
  why TEXT, row_ref TEXT, by TEXT NOT NULL, created_at TEXT NOT NULL);
-- append-only: verdicts, picks and decisions are never rewritten (report §4)
CREATE TRIGGER IF NOT EXISTS verdict_no_update BEFORE UPDATE ON verdict BEGIN SELECT RAISE(ABORT, 'verdict is append-only'); END;
CREATE TRIGGER IF NOT EXISTS verdict_no_delete BEFORE DELETE ON verdict BEGIN SELECT RAISE(ABORT, 'verdict is append-only'); END;
CREATE TRIGGER IF NOT EXISTS pick_no_update BEFORE UPDATE ON pick BEGIN SELECT RAISE(ABORT, 'pick is append-only'); END;
CREATE TRIGGER IF NOT EXISTS pick_no_delete BEFORE DELETE ON pick BEGIN SELECT RAISE(ABORT, 'pick is append-only'); END;
CREATE TRIGGER IF NOT EXISTS decision_no_update BEFORE UPDATE ON decision BEGIN SELECT RAISE(ABORT, 'decision is append-only'); END;
CREATE TRIGGER IF NOT EXISTS decision_no_delete BEFORE DELETE ON decision BEGIN SELECT RAISE(ABORT, 'decision is append-only'); END;
```

`origin` is `hand` or `generated-from:<material sha256>`. A finding id is the first 16 hex of
`sha256(subject_name \t persona_id \t dimension \t text \t citation_hash)` — stable across runs, so the same point raised
again has the same id.

## Task 1 (worker A): domain — hashes, panel query, citations, refusals, matrix, delta, trigger classifier

**Files (owned):** `src/domain/{hash.rs, query.rs, citation.rs, refuse.rs, matrix.rs, delta.rs, trigger.rs}`; unit tests in each file (`#[cfg(test)] mod tests`). Read `src/domain/model.rs` first; do not edit it (ask).

**Interfaces — Produces:**
- `hash::sha256_hex(bytes: &[u8]) -> String`; `hash::canonical_json(v: &serde_json::Value) -> String` (keys sorted, no whitespace); `hash::subject_hash(kind: SubjectKind, atts: &[Attachment]) -> String` = sha256 of `kind\n` + sorted `label\thash\n`; `hash::panel_hash(query: &str, ids: &[String]) -> String`; `hash::finding_id(subject: &str, persona: &str, dimension: &str, text: &str, citation_hash: &str) -> String` (16 hex).
- `query::parse(q: &str) -> Result<Vec<Term>, Refusal>`: comma-separated `<N> <tag>` terms; `N` ≥ 1; tag lower-cased; `others`/`other` reserved. `query::resolve(terms: &[Term], personas: &[Persona]) -> Vec<String>`: terms in query order, personas within a term by id ascending, each persona taken once (first term wins), `others` = personas carrying none of the query's other tags.
- `citation::resolve(c: &str, ev: &RunEvidence) -> Result<String, Refusal>`; grammar `<label>[#<locator>]` for the subject, `cmp:<name>/<label>[#<locator>]` for a comparator; returns `<attachment hash>#<locator>`. Locator rules: `aria-json` — a node id present in `AttachmentView.aria_ids`; `diff` — `L<n>` with 1 ≤ n ≤ `lines`; `image`/`file` — any text, unchecked. `citation::citation_hash(resolved: &[String]) -> String` (sorted, joined by `\n`, sha256; empty list → sha256 of "").
- `refuse::validate(v: &VerdictInput, cx: &VerdictContext) -> Result<ValidVerdict, Refusal>` applying, in this order: persona in run (R8), each line: dimension (R5), range (R4), `anchor_met` ∈ lens anchors and ≤ score, evidence allowed by lens (R14), seen ⇒ ≥1 citation (R1), every citation resolves (R2), comparator named and not in run ⇒ must be `recalled` (R3), dismissed (persona, citation_hash) with a blocker ⇒ R12; then pick (R9: lens asks ⇒ present; reason non-blank; choice ∈ `cx.pick_options`).
- `matrix::build(rows: &[ScoreRow], stakes: &BTreeMap<String, Stake>, lenses: &[Lens], agg: Aggregate) -> Result<Matrix, Refusal>` (`lenses` fixes the column order): `Aggregate::AcrossStrata` → `strata_average_refused`. Strata in order primary, secondary, bystander; empty strata omitted; per (stratum, lens, dimension): every persona's score, `median` (f64; even count → mean of the two middle values — the only arithmetic mean allowed, inside one stratum), `min`, `max`, `blockers`. `Matrix` has no field that spans strata. `matrix::render_table(m: &Matrix) -> String`: markdown, one row per persona under a stratum heading row, one column per `lens:dimension`, then a `median` row per stratum.
- `delta::compute(before: &[ScoreRow], after: &[ScoreRow], step: i64) -> Delta`: per (persona, lens, dimension) `before`, `after`, `moved`; `blockers_before`, `blockers_after`; `regressions` = cells where after < before − step; `landed = regressions.is_empty() && (blockers_before == 0 && blockers_after == 0 || blockers_after < blockers_before)`. `step` = the lens's anchor spacing (2 for 1/3/5).
- `trigger::parse_config(s: &str) -> Result<TriggerConfig, Refusal>` (R11; unknown quorum → `invalid_config`); `trigger::paths_from_diff(diff: &str) -> Vec<String>` (from `diff --git a/x b/y` and `+++ b/` lines, `/dev/null` skipped, sorted, unique); `trigger::classify(cfg: &TriggerConfig, paths: &[String]) -> Classification` (globset per rule; highest quorum human > high > low > none; unmatched paths → `none`; lists every matched rule and path).

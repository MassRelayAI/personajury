# Playbooks

Short worked stories, in plain words, of how a jury helps with a real job. Each one walks through a run from the files you
attach to the decision you make. They are not rules. For the rules, see [`skills/running-a-jury`](../../skills/running-a-jury).

| playbook | use this when… |
|---|---|
| [Fix a marketing site before people see it](marketing-site.md) | you are about to launch or redo a site, and want it clear, honest and free of AI slop |
| [Make docs a newcomer can follow](docs-and-readme.md) | your README or docs lose people before the first run |
| [Pick a name or a logo](pick-a-name-or-logo.md) | you have a few candidates and must choose one |
| [Test a deck or a pitch](deck-or-pitch.md) | a client, a CFO or a board will read your slides without you there |
| [Check a change in a pull request](a-change-in-a-pull-request.md) | you want only the changes that need a jury to get one, and to know when the agent may apply the fixes |

Every number in these pages points at a file: a report, a fixture, or the public CompareGraph report.

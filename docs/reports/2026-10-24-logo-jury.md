# The logo was picked by a PersonaJury jury

The first real use of PersonaJury outside its fixture was choosing its own logo. The run followed the loop in
`skills/running-a-jury`:
- one brief per persona;
- one subagent per brief, each in a private folder;
- verdicts ingested, and refused when they broke the rules;
- per-stratum matrices and the forced picks.

The engine called no model; the jurors were Sonnet subagents.

## Setup
- **Subject:** `personajury-logo`, kind `design`. Each candidate was attached as one board: the mark at 16, 32, 128 and
  200 px on white and on `#0d1117`, plus the horizontal lockup on both backgrounds.
- **Lens:** `logo` v1, scale 1–5, anchors in words at 1, 3 and 5, with a forced pick. Four dimensions:
  - `reads`: legible at 16 px;
  - `fits`: says what the tool is;
  - `distinct`: no cliché, no look-alike;
  - `everywhere`: works on both backgrounds, small and large, alone and beside the name.
- **Panel:** seven composite personas of a developer tool's audience.
  - Primary (would use it): an OSS maintainer, a platform engineer, an agent-skill author, a first-month newcomer.
  - Secondary (approves it): an engineering manager, a security reviewer.
  - Bystander (passes by): a newsletter curator.
- **Spend:** 7 briefs per round, detail `compact`, model `claude-sonnet-5-5`.

## Round 1: four directions
| candidate | idea |
|---|---|
| A | twelve seat nodes around one subject node (a jury box) |
| B | three columns of nodes, 3, 2 and 1 (the strata) |
| C | a check mark drawn as nodes and edges, ending in a citation ring |
| D | a "J" built from nodes and straight edges |

Medians per stratum (primary / secondary / bystander), never averaged across strata:

| dimension | A | B | C | D |
|---|---|---|---|---|
| reads | 2 / 2 / 2 | 2 / 3 / 2 | **5 / 5 / 4** | 3 / 2 / 3 |
| fits | 3 / 2 / 3 | 3 / 2 / 3 | 4 / 3 / 3 | 3 / 4 / 4 |
| distinct | 2 / 2 / 2 | 3 / 3 / 3 | 3 / 2 / 2 | **4 / 4 / 4** |
| everywhere | 3 / 4 / 3 | 3 / 4 / 3 | **5 / 5 / 4** | 3 / 3 / 3 |

Picks: C 4 of 4 primary and 2 of 2 secondary; the bystander picked D. No blockers.

One verdict was refused (`bad_anchor`: an `anchor_met` of 2 on a lens whose anchors are 1, 3 and 5). As the skill
says, that persona answered again, given the refusal message. Its second verdict was accepted. Nobody edited it.

## Round 2: C against two refinements
The foreman read the matrix: C wins on legibility and on working everywhere, but is weak on distinctiveness. The designer
drew two refinements:
- **c2:** a larger ring with its own inner node;
- **c3:** three nodes on the long stroke, one per stratum, and D's J hook on the short stroke.

| dimension | C | c2 | c3 |
|---|---|---|---|
| reads | **4 / 4 / 4** | 3 / 3 / 3 | 2 / 2 / 2 |
| fits | 3 / 3 / 3 | 3 / 3 / 3 | 3 / 3 / 3 |
| distinct | 3 / 3 / 3 | 3 / 3 / 3 | 3 / 3 / 3 |
| everywhere | **4 / 4 / 4** | 3 / 3 / 4 | 3 / 3 / 3 |

Picks: C, 7 of 7. One verdict was refused for the same `bad_anchor` reason and answered again.

## What this run shows, and what it does not
- **The refinements failed on their own goal.** Neither raised `distinct`, and both lost legibility at 16 px. The jury
  stopped a change that looked better at 256 px, the size designers work at.
- **Scores are relative to the options in the room.** C's `reads` went from 5 in round 1 to 4 in round 2. The mark did
  not change; its neighbours did. Read a matrix as a comparison within one run. This is also why `delta` refuses runs
  whose cells differ.
- **It is not a survey.** Seven composites stand in for a developer audience and tell you where to look. They do not
  replace showing the mark to real people.
- **`bad_anchor` came up twice.** It is the commonest refusal so far: the brief states the anchors, but jurors still
  invent values between them. The brief should state the allowed `anchor_met` values explicitly.

The full verdicts, briefs and boards are kept with the maintainer's notes; this file holds the numbers.

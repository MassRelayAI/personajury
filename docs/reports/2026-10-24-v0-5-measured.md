## What the independent review found

The reviewer reproduced each finding in a scratch copy of the branch. Verdict: fix first.

| id | finding | how it was fixed |
|---|---|---|
| Critical 1 | `apply-check --latest` judged only the newest run's subject, so CI could go green while another subject escalated | it judges every subject that has runs and answers the worst (`human` > `escalate` > `advise` > `apply`), listing each; the Action passes the class from `should-run` as `--rule` when exactly one rule matched |
| Important 1 | the Action failed open when `apply-check` errored | every error (missing `jq` or binary, git, `should-run`, `check`, `apply-check`, output that is not JSON) answers `unavailable`; the default `fail-on` is `human,escalate,unavailable` |
| Important 2 | `summary --save` could write outside the project root | `invalid_report_dir` for an absolute path, a `..` component, or a path that resolves outside the root; the MCP tool's `md` and `html` are checked the same way |
| Important 3 | the summary text was not terminal-safe (ESC sequences and BEL reached the terminal) and quotes were not verbatim | ESC sequences, C0 controls but the newline, DEL and C1 are removed; quotes fold whitespace and are cut only between words |

Minor: M1 (calibration file checks were loose; now `calibration_mismatch`), M2 and M3 (CSV `r9c9`, `R1c1`, `RC1` refused; a quote opens a quoted field
only at the start of a field), M4 (file names are markdown-escaped in the step summary), M5 (the `version` input defaults to the Action's own release,
and a test ties it to the newest changelog entry) and M7 (`docs/ci.md` documents `unavailable`) were fixed. M6 (the summary counts blockers and open
findings across strata) was not reported fixed.

Shell injection from file names was probed and is not possible (inputs reach the shell through `env:`, never `${{ }}` in `run:`).
Not changed: summary table labels and column headers are still truncated by width (they are identifiers, not quotes).

## What is left open

- The Action has been tested against a local binary only, not on GitHub. The SDK example byte-compiles and holds no key, but it has not run against a model.
- The summary still counts blockers and open findings across strata ("and 23 more", "26 findings have no decision yet"). They are counts, not pooled scores.
- `uncalibrated` is `advise`, not `escalate` as the roadmap first said (D20, by the principle of D13).
- The checksum in the install script checks integrity, not authenticity: it comes from the same release as the binary.
